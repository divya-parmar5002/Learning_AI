## 2. Groq

I created an account on **Groq** and generated an API Key.

Groq is an **AI inference platform** that provides access to different Large Language Models (LLMs).

Instead of running an LLM on my own computer, my application sends a request to the Groq server.

The Groq server runs the selected AI model and sends the generated response back to my application.

---

## 3. API Key

An API Key is like a secure identity card for my application.

It tells the Groq server:

* Who is sending the request
* Whether the request is allowed
* Which account should be used

Without a valid API Key, my application cannot communicate with the Groq server.

---

## 4. Qdrant

I also created an account on **Qdrant**.

Qdrant is a **Vector Database**.

Unlike a normal SQL database, it stores vector embeddings.

It is commonly used in AI applications for:

* Semantic Search
* Retrieval-Augmented Generation (RAG)
* Long-term memory
* Finding similar information

Although conversation history can be stored and retrieved using Qdrant, the conversation context itself is usually maintained by sending previous messages to the LLM.

I will learn this in more detail later.

# 🧠 LLM API Call Flow

One of the most important concepts I learned today was how an application communicates with an LLM.

The complete flow is:

```text
User
   │
   ▼
Python Application
   │
   ▼
Groq Client
   │
   ▼
Groq Server
   │
   ▼
Selected LLM
   │
   ▼
Generated Response
   │
   ▼
Python Application
   │
   ▼
User
```

---

# 📝 Four Main Steps of an LLM API Call

## Step 1 — Authentication & Client Creation

First, the application loads the API Key from the `.env` file.

Using that API Key, a **Groq Client** is created.

The client is responsible for communicating with the Groq server.

```python
client = Groq(api_key=my_api_key)
```

Without the client, the application cannot send requests.

---

## Step 2 — Model Selection

An API can provide multiple AI models.

Before asking a question, I need to decide which model should generate the answer.

Example:

```text
llama-3.3-70b-versatile
```

Different models may have different speed, quality, and capabilities.

---

## Step 3 — Sending Messages

The next step is sending a message.

A message contains two important fields.

### Role

The role tells the model who is speaking.

There are three common roles.

### User

The person asking the question.

Example:

> Who is Virat Kohli?

---

### Assistant

The answer generated by the AI.

---

### System

The system role defines how the AI should behave.

Examples:

* You are an experienced AI Engineer.
* Answer in one sentence.
* Explain like a teacher.

The system role changes the behavior of the AI, not the question itself.

---

### Content

Content contains the actual message.

Example:

```text
Who is Virat Kohli?
```

---

# 💬 Conversation Context

One important concept I learned is **conversation context**.

The LLM understands previous messages if they are sent again with the new request.

Example:

User:

> Who is Virat Kohli?

Assistant:

> Virat Kohli is an Indian cricketer.

User:

> What is his age?

The AI understands that **"his"** refers to **Virat Kohli** because the previous conversation is included in the messages.

This is called **Conversation Context**.

---

# 📦 Response

The API returns a response object.

The response contains multiple pieces of information.

Two important parts are:

## Choices

The generated answer.

Usually, I access the first answer like this.

```python
response.choices[0].message.content
```

---

## Usage

The Usage section tells me how many tokens were used.

It usually contains:

* Prompt Tokens
* Completion Tokens
* Total Tokens

This information is useful for tracking API usage and cost.

# 💻 Code Explanation

## Import Statements

```python
import os
```

Used to read environment variables.

---

```python
from dotenv import load_dotenv
```

Loads the `.env` file.

---

```python
from groq import Groq
```

Imports the Groq client.

---

## Loading Environment Variables

```python
load_dotenv()
```

Loads all values from the `.env` file.

---

## Reading API Key

```python
my_api_key = os.getenv("GROQ_API_KEY")
```

Reads the API Key from the environment variables.

---

## Checking API Key

```python
if not my_api_key:
    raise ValueError("No API Available")
```

Stops the program if the API Key is missing.

---

## Creating Client

```python
client = Groq(api_key=my_api_key)
```

Creates a client that communicates with the Groq server.

---

## Selecting Model

```python
model = "llama-3.3-70b-versatile"
```

Chooses which AI model will generate the response.

---

## Creating Message

```python
message = {
    "role": role,
    "content": prompt
}
```

Creates a message in the format expected by the API.

---

## Messages List

```python
messages = [message]
```

The API expects a list because multiple messages can be sent for maintaining conversation history.

---

## Sending Request

```python
response = client.chat.completions.create(
    model=model,
    messages=messages
)
```

Sends the request to the Groq server.

---

## Reading the Answer

```python
answer = response.choices[0].message.content
```

Extracts only the generated text from the complete response object.

# ⚠️ Important Notes

* UV is not just a faster pip. It is a modern Python project manager.
* Never store API Keys directly inside source code.
* Always use a `.env` file for secret information.
* The client is responsible for communicating with the API.
* The model decides which AI generates the answer.
* The System role controls the AI's behavior.
* The User role contains the user's question.
* The Assistant role contains the AI's reply.
* Conversation context is maintained by sending previous messages.
* Qdrant is a Vector Database and is commonly used for semantic search and long-term memory in AI applications.
