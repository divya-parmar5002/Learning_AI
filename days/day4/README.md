# 🧠 Structured vs Unstructured Output

Whenever we ask something to an AI model, the response can generally be divided into two categories.

1. Unstructured Output
2. Structured Output

---

# What is Unstructured Output?

Unstructured output is simply normal text generated by the AI.

Example:

Prompt


Tell me about Elon Musk.


Possible Response


Elon Musk is an entrepreneur, investor and the CEO of several technology companies including Tesla and SpaceX...


This response is easy for humans to understand.

However, it is difficult for software applications to directly use specific information from this paragraph.

For example, if an application only needs:

- Name
- Occupation
- Company

it must first search through the paragraph and extract the required information.

This process is known as **Text Parsing**, which becomes difficult and inefficient for large documents.

---

# Example of Unstructured Output

Suppose the AI returns:


Hello! I am Divya Parmar. I am a Student and want to learn AI.
My email is abc@gmail.com.
My contact number is XXXXXXXXXX.


A human can immediately identify:

Name → Divya Parmar

Occupation → Student

Email → abc@gmail.com

Contact Number → XXXXXXXXXX

However, for a computer, this is simply one long string.

The computer must process the entire paragraph before finding the required information.

---

# What is Structured Output?

Structured Output means the AI returns information in a predefined format.

Instead of writing a paragraph, it organizes the data into separate fields.

Example:

{
  "Name": "Divya Parmar",
  "Occupation": "Student",
  "EmailID": "abc@gmail.com",
  "Contact_Number": "XXXXXXXXXX"
}


Now the application can directly access the required values.

Example:


data["Name"]


or


data["EmailID"]


No text parsing is required.

This makes structured output much easier for software applications.

---

# Why is Structured Output Important?

Imagine extracting information from:

- 10 resumes
- 500 resumes
- 10,000 resumes

If every response is plain text, the application must process every paragraph.

If every response is structured JSON, the application can immediately read the required fields.

This makes AI applications faster, simpler and more reliable.

---

# What is JSON?

JSON stands for:

**JavaScript Object Notation**

Although it was originally created for JavaScript, today it is one of the most popular data formats used by almost every programming language.

JSON stores data in **Key-Value** pairs.

Example:


{
  "name": "Divya",
  "age": 21,
  "city": "Indore"
}


Here,

- name is the key
- Divya is the value

Similarly,

- age → 21
- city → Indore

Because JSON follows a fixed structure, it is easy for both humans and computers to understand.

---

# Why Do We Use JSON?

JSON has many advantages.

- Easy to read
- Easy to write
- Lightweight
- Platform independent
- Language independent
- Easy to parse
- Used by almost every REST API

Most modern frameworks use JSON.

Examples:

- FastAPI
- Flask
- Django REST Framework
- OpenAI API
- Groq API

---

# What is Pydantic?

Pydantic is a Python library used to create **Data Models** and validate data.

Instead of manually checking every field, we define the expected structure inside a Python class.

Example:


from pydantic import BaseModel

class Info(BaseModel):

    Name: str
    Occupation: str
    EmailID: str
    Contact_Number: str


This class tells Python:

"I expect my data to contain these four fields, and every field should contain a string."

Pydantic helps keep data organized and validates that it follows the expected structure.

---

# What is a JSON Schema?

A JSON Schema is a description of how JSON data should look.

It specifies:

- Required fields
- Data types
- Structure
- Validation rules

Instead of writing the schema manually, Pydantic can generate it automatically.

Example:


schema = Info.model_json_schema()


This converts the Pydantic model into a JSON Schema.

The generated schema is then shared with the AI model so it knows exactly which structure to follow.

---

# Why Do We Need Both JSON and Pydantic?

JSON and Pydantic are different concepts.

Pydantic defines the expected structure of the data.

JSON is the format used to represent that structured data.

Together they help AI models generate responses that are easy for applications to process.

# 🧠 Prompt Engineering Basics

While learning JSON and Pydantic, I also learned one of the most important concepts in AI Engineering called **Prompt Engineering**.

Initially, I thought that after creating a Pydantic model and generating a JSON Schema, the AI would automatically understand what I wanted.

However, I learned that this is **not true**.

A Large Language Model (LLM) does **not** understand Python code directly.

It only understands **natural language instructions (text)**.

This means that creating a Pydantic model is **not enough**.

I must also clearly explain the task that I want the AI to perform.

---

# Why Doesn't the AI Understand My Python Code?

Suppose I create the following Pydantic model.


class Info(BaseModel):
    Name: str
    Occupation: str
    EmailID: str
    Contact_Number: str


This class is understood by **Python**, not by the AI model.

The AI never reads my source code.

Before sending the request, Python executes the program and prepares the prompt.

The AI only receives the final text that is sent through the API.

That is why I convert the Pydantic model into a JSON Schema and include it inside the prompt.

---

# Why Do We Use `model_json_schema()`?


schema = Info.model_json_schema()


This function converts the Pydantic model into a JSON Schema.

The schema becomes plain text, and the AI can understand text.

Instead of sending Python code, we send a structured description of the expected output.

---

# Why Do We Use `f""" """`?

Python provides **f-strings** to combine text with variables.

Example:


name = "Divya"

print(f"Hello {name}")


Output:


Hello Divya


Without using `f`, Python would print:


Hello {name}


instead of replacing `{name}` with its value.

In today's program, I used:


system_prompt = f"""
Extract the personal information from the given text.

Follow this schema.

{schema}
"""


The `f` allows Python to insert the generated schema into the prompt before sending it to the AI.

---

# Why Is the Prompt Written in Complete English?

This was one of the biggest questions I had while learning.

I wondered:

> "If I already created the schema, why do I still need to write a long instruction?"

The answer is simple.

The schema only tells the AI **what the output should look like**.

It does **not** tell the AI **what task to perform**.

The prompt explains the task.

The schema explains the structure.

Both are required.

---

# Example

Suppose I only send the schema.

The AI sees something like:

```text
Name
Occupation
EmailID
Contact_Number
```

The AI still does not know what I want.

Should it:

- Explain the schema?
- Create sample data?
- Translate the schema?
- Extract information?

The task is unclear.

---

Now consider this prompt.

```text
Extract the personal information from the given text.

Follow this schema.

Return only valid JSON.
```

Now the AI clearly understands:

- What information to extract.
- Which schema to follow.
- Which format to return.

The result is much more accurate.

---

# Why Do We Write "Return JSON"?

Another question I had was:

> "I already used `response_format={"type":"json_object"}`. Why do I still tell the AI to return JSON?"

The answer is that these two things have different responsibilities.

### `response_format`

This tells the **API** that we expect a JSON object.

### System Prompt

The system prompt tells the **AI model** how to perform the task.

Both work together to increase the chances of receiving clean, structured output.

This is considered a good practice in Prompt Engineering.

---

# Good Prompt vs Bad Prompt

## ❌ Bad Prompt

```text
Resume

Name

Email

Phone
```

This prompt is too vague.

The AI may not understand the exact task.

---

## ✅ Better Prompt

```text
Extract the Name, Email Address, and Phone Number from the given resume.

Return the result in valid JSON.
```

Now the task is much clearer.

---

## ✅ Best Prompt

```text
You are an Information Extraction Assistant.

Extract only the fields defined in the schema.

Return ONLY valid JSON.

Do not add explanations.

Do not add markdown.

If any field is missing, return null.

Follow the schema exactly.
```

This prompt gives the AI very clear instructions and reduces the chances of unexpected output.

---

# Why Prompt Engineering Is Important

Prompt Engineering is the process of writing clear instructions so that an AI model produces accurate and reliable responses.

A better prompt usually produces a better response.

Even if two developers use the same AI model, they may receive different outputs because they wrote different prompts.

Therefore, writing good prompts is an essential skill for every AI Engineer.
